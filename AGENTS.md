# Project Agent Guide

This repository is the full Podcast Speaker AI Investment Mentor project.

Current workspace layout:

- `legacy/`: frozen earlier transcription, extraction, case-only RAG and principle-assisted Mentor implementations. Preserve comparison behavior; only relocation or explicit regression fixes belong here.
- `transcription/`: active formal transcription worker, normalization and source-quality gate. Read its `AGENTS.md` before editing.
- `knowledge/`: active, versioned L1-L4 offline extraction and review-bound release publication. Read its guide before editing.
- `mentor_agent/`: active local retrieval, structured applicability/answers and loopback HTTP service over reviewed private releases. Read its guide before editing.
- New production code must not import `legacy/`. Promote reviewed utilities with focused tests instead of copying an entire POC.

## Project Purpose

The long-term goal is to build an AI Investment Mentor from historical Gooaye 股癌 podcast content. The system should learn patterns in:

- market and industry analysis logic
- decision process and reasoning
- risk attitude
- uncertainty handling
- exception conditions
- view revision
- teaching style
- cross-case behavioral patterns

The goal is not automated trading and not direct order placement.

## Global Invariants

- Raw data is never overwritten by derived artifacts.
- Before bulk derived processing, preserve raw versions and rejected outputs in
  a verified private snapshot and test restore into a separate new directory.
  Keep source hashes and use new output versions; never remove read-only
  protection to edit raw in place. A same-device snapshot is not off-device backup.
- Structural transcript validation is not content-quality certification. Extraction requires a review bound to the exact transcript version; never fabricate a passing review.
- Preserve the pre-rebuild tag `archive/pre-rebuild-2026-11-05`. Private canonical data is not renamed or regenerated by a source-tree migration.
- Every derived layer must trace back to episode, timestamp, and source IDs.
- Preserve audio SHA-256, model, config, package versions, and run metadata.
- Do not treat historical market commentary as current investment advice.
- Do not encode the speaker model as a fixed unconditional personality.
- Do not build a full Agent, fine-tuning workflow, RAG, embeddings, or vector database unless explicitly requested.
- Separate planning estimates from measured results.
- Prefer project-relative paths for repository artifacts.
- Phase 2 semantic extraction should be LLM-based, whole-episode-aware, evidence-grounded, hierarchical, and multi-tag.
- Do not use deterministic keyword segmentation, fixed episode-position weighting, fixed-duration windows, or single-label classification as the main semantic method.
- Future Level 3 principles are episode-local and provisional. Do not treat them as confirmed long-term speaker rules.
- Future Level 4 principles must preserve supporting cases, counterexamples, conflicts, evolution, and confidence.
- A principle is an abstraction from evidence. Do not count it as an additional independent evidence item.
- Terminology corrections are annotations/context and must not destructively rewrite raw transcript evidence.

## Public / Private Artifact Boundary

- Private repo is the canonical source of truth for complete data, outputs, reports, and internal documents.
- Public repo contains source code and curated public derivatives only.
- Do not create a `private/`, `private_data/`, `internal/`, or `full_outputs/` directory inside this public repo.
- Do not copy complete private artifacts into this public repo.
- Do not use public samples as production or canonical pipeline inputs.
- All complete transcripts, semantic outputs, evaluation traces, model response traces, and internal reports must remain in the private repo.
- A public artifact must be synthetic, redacted, summarized, or aggregated.
- Before creating a public artifact, identify its private source and record the relationship in `docs/public_artifacts.md` or the private artifact manifest.
- Do not expose absolute local paths, credentials, private URLs, or private repository details in public files.
- Do not move or delete canonical private artifacts solely to simplify public presentation.
- If a public artifact name is easy to confuse with a canonical private artifact, rename it to clearly mark it as a public derivative, for example with `_public`, `_aggregate`, `_redacted_sample`, or `_synthetic_sample`.
- When unsure whether an artifact is safe for public use, keep it private and report it as unresolved.

## Simplicity And Organization Rules

- Keep the repository easy to read before making it more complete.
- Start from `README.md`; split details into separate docs only when the README becomes too long or the topic is independently useful.
- Prefer fewer, clearer modules over many tiny modules. Split a module only when a step has a distinct responsibility, reusable implementation, or likely replacement path.
- POC folders are sandbox/playground areas. Do not couple future production architecture to POC internals unless the user explicitly promotes a component.
- Prefer one canonical artifact per stage. Avoid producing JSON, JSONL, CSV, and Markdown versions of the same result unless each has a real consumer.
- Merge small configuration or terminology files when one shared source of truth is clearer. Split them later if maintenance pressure appears.
- Temporary experiments may be created while investigating. Once they are no longer useful, either remove them or move useful references into `legacy`/`tmp` rather than leaving them in the active path.
- Do not keep obsolete scripts in the main workflow. If they remain useful as references, move them under a clearly named legacy location.
- Keep human-facing reports concise and reviewable; do not generate a separate report for every intermediate JSON file.
