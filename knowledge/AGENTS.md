# Offline Knowledge Rules

Read root policy. This module consumes hash-bound private source versions.
Reviewed extraction requires accepted sources. Explicit candidate extraction may
use structurally verified drafts, retaining source issues and separate reviewer
commentary without filling missing context. Assess ambiguity per case, not as an
automatic whole-episode rejection. Candidate outputs must remain quarantined;
never weaken release acceptance or relabel a hold as an accepted episode review.
Explicit hash-bound selected-case source-fitness and semantic review may publish
case-only evidence via knowledge_case_release.v1. Preserve the original hold and
all material limitations; unresolved claim-bearing ambiguity cannot be approved.
L2 cases are the evidence
authority; L3/L4 are revisable abstractions, never independent evidence.
Keep provider/model proposals separate from deterministic provenance accounting.
Do not import legacy modules. Tests use synthetic source/review fixtures only.
Online answering belongs in mentor_agent, not in extraction prompts.

Active artifacts use knowledge.v2. Account for every L1 source region and every
L2 thread disposition; evidence must agree with the declared threads. Never
infer event independence from episode/date counts. Hypotheses remain ineligible
regardless of record count. L4 must account for known overlapping L3
counterevidence, including ineligible ancestors; exclusions need a reviewable
reason. Do not silently migrate v1 outputs or reuse their semantic acceptance.
